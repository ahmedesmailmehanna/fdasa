# Five Days at STEM Alex (fdasa)

A FNAF-style survival horror game by **Byasa Games**. You play the new, much-hated principal of STEM Alex. The students petitioned to have you removed, the Ministry accepted, and you leave next week, so they make your last five school days hell. Each "night" is a school day, **9 AM to 3 PM**, survived from the Principal Office using doors and cameras.

This README is developer documentation: how the project is set up and how the major systems work. For what's next, see [`TODO.md`](TODO.md).

## Naming conventions

These names are how systems find each other, so they matter.

| Thing | Format | Example |
|---|---|---|
| Spot (graph node) | `F<floor>_<Name>` | `F1_HallL2`, `F0_Bathroom`, `F2_AtriumL` |
| Camera | `F<floor>_CAM_<Name>` | `F1_CAM_HallL` |
| Student graph file | `graph_<lowercase name>.tres` | `graph_bees.tres` |
| Student asset folder | lowercase name | `assets/students/bees/` |
| Student id | `Students.Id.<UPPERCASE>` | `Students.Id.BEES` |

The **floor prefix is the floor**. The tool, the generator and the floor switch all read it from the name.

Floors: `F0` ground floor (fab lab), `F1` first floor (Principal Office, main gameplay floor), `F2` / `F3` upper floors. Gameplay cameras currently cover floors 0 and 1.

## How a night works

### Scene tree (`night.tscn`)

```
Night            (night.gd)
├── GameManager  (game_manager.gd)   ← MUST stay first, see "Gotchas"
├── TestStudent  (animatronic.gd)    ← Bees, for testing
└── CameraSystem (camera_system.tscn)
```

### Startup order

1. Every child runs `_ready()` first, top to bottom:
   - `GameManager` joins the `"game_manager"` group.
   - Each student finds GameManager through that group, registers its starting spot, joins the `"students"` group, and **starts disabled**.
2. `Night` runs `_ready()` last (parents always run after their children):
   - Picks the config: `GameState.current_night` if the menu set one, else the `Test Config` export.
   - Sets Joe's level on GameManager.
   - Calls `set_level()` on every node in `"students"` with its level from the config. Level > 0 wakes a student up.

Nodes find each other through **groups** (tags added with `add_to_group()`), not hardcoded paths.

## Students and movement

### Graphs

Each walking student has its own `StudentGraph`: a weighted, **directed** graph.

```gdscript
"F1_HallL2": {"F1_HallL3": 3, "F1_MrNabil": 1, "F1_HallL1": 1}
```

- Key = the spot the student is on. Value = where they can go next, with a weight.
- Weights are **relative**: 3 vs 1 means three times as likely. They don't need to add to 100.
- Directed means one-way paths are natural (Bees' atrium drop from floor 2 has no way back up).
- An empty `{}` is a **stop spot**: the student stays there. Correct for `F1_OfficeHall` (the door, where attack logic takes over), a bug anywhere else.

### Move roll (`animatronic.gd`)

Every student counts down a random wait (`move_interval_min`..`max` seconds). At zero it rolls:

**Step 1, does it move?**

```
move_weight = aggression + Joe's aggression bonus
move_chance = move_weight / (move_weight + stay_weight)
```

- `aggression` is the student's level for the night: **0 = disabled**, 1–20 = difficulty.
- The chance never reaches 100%, so no level is perfectly predictable.
- `stay_weight` (default 10) is how lazy a student is overall. Aggression 10 = 50/50.

**Step 2, where to?** A weighted random pick from the current spot's neighbors (`rand_weighted`).

### Joe (currently inside `GameManager`)

Joe doesn't walk. His music level (0–100) rises while he's blasting and decays when stopped, and it affects **every** student:

- adds to their aggression (`get_aggression_bonus()`)
- speeds up their countdown, even mid-wait (`get_speed_multiplier()`)

Joe's own level (0–20) scales both effects between the `*_at_level_1` and `*_at_level_20` exports. Level 0 disables him entirely. He'll move into his own node once his real behavior (cameras, volume control) is built.

## Nights and difficulty

`NightConfig` (a Resource) holds one level per student (0–20) plus night-wide settings. **Levels are fixed for the whole night.**

- **Story nights:** saved files like `data/nights/night_1.tres`, edited in the Inspector.
- **Custom night:** a `NightConfig.new()` built from the menu's sliders.
- Every student is always in the scene. Not in tonight's roster = level 0.

The main menu (not built yet) will do:

```gdscript
GameState.current_night = load("res://data/nights/night_3.tres")
get_tree().change_scene_to_file("res://scenes/night.tscn")
```

`GameState` is the project's only autoload, because it's the one thing that must survive the scene change.

## Cameras and art

- `CameraMap`: each camera id maps to the spots it can see. One feed can see several spots, and spots no camera sees are blind spots.
- **Backgrounds:** one per camera.
- **Overlays:** one per student × camera × spot that camera sees, drawn on top of the background.
- Blind spots need no art. A spot two cameras see needs two overlays.

How it's wired:

- `GameManager.occupants` holds a **list** of students per spot, and emits `student_moved(student, from, to)` after every move.
- `CameraSystem.show_camera(id)` draws the background, then asks GameManager who stands on each spot that camera sees, and asks each student for its overlay with `get_frame_for(camera_id, spot_id)`.
- The feed redraws live when a student walks into or out of the current camera's spots.
- Camera buttons and the floor switch are built from the camera map at startup: the floor prefix groups them, and the part after `_CAM_` is the button label.
- Overlays draw in the order the camera map lists the spots, so list them **back to front**.

Art paths:

```
res://assets/cameras/F1_CAM_HallL.png
res://assets/students/bees/F1_CAM_HallL/F1_AtriumL.png
```

Missing art is fine: the debug label (top left, `CameraSystem.show_debug`) lists who is on the camera and flags `(no art yet)`, so the game is playable before any art exists.

## Tools and workflows

### Student paths tool (`tools/student-paths-tool.html`)

A visual editor for spots and student graphs. Open it in any browser.

- Per-floor views, cross-floor paths shown as dashed spots at the edges
- Click to select, **Shift+click** (or Connect) to add a path, drag or arrow keys to move
- Weights with live percentages, stop-spot and no-way-in checks
- Export: a student's `g.nodes = {...}` block, or the spot list `l.nodes = PackedStringArray([...])`
- **Save file / Open file** for `student_paths.json`. Without Save file, work only lives in that browser

### Graph generator (`scripts/dev/generate_graphs.gd`)

Attach to a node in a throwaway scene and run that scene. It builds the spot list, every student graph and the camera map, **validates everything** (unknown spots, paths into spots with no entry), and only saves to `data/graphs/` if there are no errors.

### Asset layout tool (`scripts/dev/build_asset_layout.gd`)

Open in the Script editor, **File > Run** (Ctrl+Shift+X). Creates every asset folder the lookup expects, prints missing and unused images, and writes `assets/asset_checklist.md`. Never deletes anything.

### Changing paths

1. Edit in the tool, **Save file**
2. Copy the student's `g.nodes` block into its `_<name>_graph()` in the generator
3. If you added spots: copy the spot list into `_locations()` too (the generator rejects unknown spots)
4. Run the generator, then the asset layout tool

### Adding a new student (walker or harmless NPC)

1. **+ Student** in the tool, draw the graph, add a `_<name>_graph()` + `_save()` in the generator
2. Update `_locations()` if any spots are new
3. Add to `Students.Id`, and a level field in `NightConfig` + `get_level()`
4. Add an `Animatronic` node under `Night` (Student Id, graph, starting spot)
5. Run the generator, then the asset layout tool

### Testing a night

Set levels in `data/nights/night_test.tres`, make sure it's in the `Night` node's **Test Config**, and run `night.tscn`. Movement prints to the **Output** tab.

## Gotchas

- **`GameManager` must stay above** anything that looks it up in `_ready()`. Sibling order is `_ready()` order.
- **`%UniqueName`** silently returns `null` unless the node is marked "Access as Unique Name".
- A script's `extends` must match its scene root type (`Control` script → `Control` root).
- Empty Inspector for a script → save the script, reselect the node, or reload the project.
- `print()` goes to **Output**, errors go to **Debugger → Errors**.
- Nothing happens when a night starts → the `Night` node has no **Test Config**.
- A class never joins a group by itself, only `add_to_group()` does.
- Rename or move files **inside Godot's FileSystem panel**, not in your file explorer, so references update.
